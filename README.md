# Я.МОЛОД — доступ открыт?

Браузерная сюжетная игра для большого экрана. Реализованы пролог с двумя ветками, знакомство с «Ямолод», правила квеста и первая станция «МедиаЛаб» по материалам `ref/`.

HTML, CSS и JavaScript ES-модули без сборки. Canvas рисует пиксельный мир, а звук синтезируется через Web Audio. Сетевые комнаты, голосования, общий таймер мини-игры и прогресс команды работают через Firebase.

## Запуск

Из корня проекта:

```powershell
python -m http.server 8000 --bind 127.0.0.1
```

Открыть **http://127.0.0.1:8000/** в современном браузере. Нужен HTTP: открытие `index.html` через `file://` не подходит для ES-модулей. Остановка сервера — `Ctrl+C` в терминале. Для запуска подойдёт любой другой сервер статических файлов.

Для прохождения без телефонов выберите **Локальная репетиция** на экране входа ведущего. Монтаж в «МедиаЛабе» будет доступен на том же экране.

### Игра с телефонами на GitHub Pages

1. В [настройках GitHub Pages](https://github.com/Daikeri/tanyusha-quest-game/settings/pages) выберите **Settings → Pages → Source → GitHub Actions**. Workflow `Publish game to GitHub Pages` запускается после попадания изменений в `main`. Его также можно запустить вручную из вкладки Actions. [Документация GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).
2. В проекте Firebase `yamolod-game` включите **Authentication → Sign-in method → Email/Password и Anonymous**. В **Realtime Database → Rules** опубликуйте содержимое [`database.rules.json`](database.rules.json). Правила разрешают управление сессией указанному UID ведущего. [Документация правил Firebase](https://firebase.google.com/docs/database/security).
3. Откройте [игру на GitHub Pages](https://daikeri.github.io/tanyusha-quest-game/) и войдите в аккаунт ведущего. Игра автоматически создаст сессию и покажет QR на стартовом экране. Дождитесь подключения участников и нажмите **Начать историю**. При локальном запуске с `localhost` или `127.0.0.1` QR тоже ведёт на опубликованную страницу.

Сессия, игроки и ответы хранятся в Realtime Database. Ведущий управляет сюжетом в браузере. Когда итог готов, пробел публикует его на телефонах и продолжает постановку. При ничьей или отсутствии голосов ветку выбирает ведущий. Перезагрузка телефона восстанавливает его ответ. При перезапуске истории игра закрывает прежнюю комнату и показывает QR новой комнаты.

## Управление

| Действие | Управление |
| --- | --- |
| Начать | «Начать историю» |
| Раскрыть реплику / перейти к следующей | Пробел или «Далее» |
| Продолжить переписку | Пробел или «Продолжить» |
| Пауза и возобновление | «Пауза» в верхней строке или «Продолжить» на экране паузы |
| Повторить историю | «Пройти ещё раз» на экране окончания |
| Звук, полный экран | Кнопки в верхней строке |

Движения, затемнения и камера выполняются автоматически. Пробел во время этих действий не ставится в очередь. Удержание клавиши не пролистывает историю. При переходе в другую вкладку активное прохождение ставится на паузу.

### Локальная проверка голосования

1. Дойти до «Прими решение» в сцене 02.
2. Выбрать А (согласие) или Б (отказ) на экране голосования.
3. Дождаться 30 секунд либо нажать «Завершить отсчёт».
4. Нажать «Продолжить» или пробел, чтобы открыть выбранную реплику.

Без заданной ветки игра продолжает ждать. До завершения отсчёта выбор можно изменить. После фиксации результат сохраняется. В сетевой игре варианты для ведущего появляются при ничьей или отсутствии голосов.

До начала истории ведущий выбирает полную версию на пять станций или сокращённую на три. В «МедиаЛабе» оба монтажа делаются за общие 90 секунд. На втором этапе сохраняется порядок кадров первого. После истечения времени ведущий продолжает историю, и команда получает ключ по завершении станции независимо от результатов участников.

Состояние сюжета хранится в памяти. После обновления страницы ведущего игра открывается на экране входа. На телефоне обновление страницы во время задания восстанавливает черновик текущего монтажа. Звук включается только после действия пользователя.

## Расширение

- `src/scenes.js` — сценарные данные и ветвления. Новые сцены на существующих механиках добавляются здесь.
- `src/engine.js` — контракты JSDoc, проверка сценария, часы, проигрыватель и локальный адаптер выбора.
- `src/resources.js` — персонажи, палитра, реестр локаций, поз, музыки и вложений.
- `src/world.js` — Canvas, пиксельные спрайты, декорации, маршруты и камера.
- `src/ui.js`, `src/audio.js`, `src/main.js` — представления, звук и подключение компонентов.

Описание контрактов и пример новой сцены: [авторинг сцен](docs/architecture/scene-authoring.md). Архитектурные инварианты: [core](docs/architecture/core.md). Фактический объём: [current-state](docs/architecture/current-state.md).

## Проверки

При запущенном HTTP-сервере открыть **http://127.0.0.1:8000/tests/**. Страница выполняет 13 проверок без сторонних библиотек: ссылки, пауза, отмена, голосование, параллельные действия, перезапуск и обе ветки.

Для дополнительной браузерной проверки нужен Python-пакет `playwright` и установленный Microsoft Edge:

```powershell
python tests/browser_check.py
```

Скрипт проходит обе ветки, проверяет управление и разные размеры окна, сохраняет снимки в игнорируемую `.artifacts/`. Зависимость нужна только этому QA-скрипту, не игре и не странице проверок движка.

Для проверки телефонов и правил базы запустите локальный эмулятор командой `firebase emulators:start --only database --project demo-yamolod`, оставьте статический сервер на порту `8000` и выполните `python tests/network_check.py`. Проверка использует тестовые идентификаторы в эмуляторе.
