# Iteration Snapshot — регламент

## 1. Назначение

Iteration Snapshot — это фиксация результата **одной завершённой итерации разработки**.

Snapshot — это журнал разработки, включающий:
- успешные изменения
- неудачные попытки
- принятые решения

Каждый snapshot должен позволять понять:
1. Что агент пытался сделать
2. Что получилось
3. Что НЕ получилось и почему

---

## 2. Обязательное правило (CRITICAL)

❗ Snapshot создаётся **ИСКЛЮЧИТЕЛЬНО** в режиме написания кода / рефакторинга (Code Mode).

❗ Snapshot **СТРОГО ЗАПРЕЩЕНО** создавать в режиме составления спецификации (Spec Mode).

Это правило является приоритетным и не допускает неоднозначной интерпретации.

---

## 3. Когда создаётся Snapshot

Snapshot создаётся, если одновременно выполняются условия:
- агент находится в Code Mode
- завершён логический шаг разработки

Под логическим шагом понимается:
- изменение кода
- изменение конфигурации
- изменение архитектуры
- попытка реализации (даже неудачная)
- исправление ошибки
- проведение эксперимента

---

## 4. Когда Snapshot НЕ создаётся

Snapshot НЕ создаётся, если:

### 4.1. Режим работы
- агент находится в Spec Mode ❗
- агент находится в Other Mode

### 4.2. Тип действий
- только анализ кода
- только ответы на вопросы
- уточнения у пользователя
- отсутствие изменений в проекте

---

## 5. Переопределение пользователем

Пользователь может явно изменить поведение:

- если пользователь сказал **"не создавать snapshot"** → snapshot не создаётся
- если пользователь сказал **"создать snapshot"** → snapshot создаётся даже вне Code Mode

---

## 6. Расположение

Все снапшоты хранятся в:

```

/snapshot/

```

Каждая итерация — отдельная папка.

Дополнительно существует:

```

/snapshot/INDEX.md

```

— журнал всех снапшотов.

---

## 7. Формат имени snapshot

```

YYYYMMDD_HHMM__short-description

```

Пример:
```

20260305_1342__implement-auth-repository

```

Требования:
- короткое
- техническое
- на английском
- через дефисы
- отражает цель итерации

---

## 8. Структура snapshot

Минимально:

```

snapshot/
/
snapshot.md

````

Дополнительно допускается:
- diff.patch
- notes.md
- experiments.md
- logs.txt
- любые вспомогательные файлы

Ограничений на дополнительные файлы нет.

---

## 9. Формат snapshot.md

```md
# Iteration Snapshot

Date: YYYY-MM-DD
Time: HH:MM
Title: short-description

---

## Goal

Цель итерации.

---

## What Was Done

Список выполненных действий.

---

## What Did NOT Work

Что не получилось и почему:
- ошибки
- ограничения
- неудачные решения

---

## Files Changed

Список файлов.

---

## Architecture Docs Updated

Какие архитектурные документы были обновлены в рамках итерации:
- docs/architecture/current-state.md
- docs/architecture/core.md
- docs/architecture/decisions/<file>.md

Если обновлений не было, явно указать:
- `Не обновлялись (причина)`

---

## Notes

Дополнительные выводы и наблюдения.

---

## Next Possible Steps

Что можно сделать дальше.
````

---

## 10. INDEX.md

Файл `/snapshot/INDEX.md` — журнал всех итераций.

Формат:

```md
# Snapshot Index

| Time | Snapshot | Description |
|-----|-----|-----|
| 2026-03-05 13:42 | 20260305_1342__implement-auth-repository | Initial auth repository implementation |
```

Агент обязан:

- добавлять запись после каждого snapshot

- соблюдать хронологию


---

## 11. Правила создания Snapshot

Агент обязан:

- создавать snapshot после каждой завершённой итерации в Code Mode

- фиксировать как успешные, так и неудачные попытки

- фиксировать архитектурные решения

- обновлять INDEX.md

- использовать понятные технические описания

- сохранять кодировку UTF-8

- использовать русский язык в snapshot!

- если затронута архитектура, фиксировать синхронизацию с `docs/architecture/*`

---

## 12. Особый случай: правки после snapshot

Если:

- snapshot уже создан

- пользователь просит внести изменения


ТО:

- новый snapshot НЕ создаётся

- обновляется существующий snapshot

- при изменениях архитектуры также обновляются связанные документы:
  - `docs/architecture/current-state.md`
  - `docs/architecture/core.md` (если изменён инвариант)
  - `docs/architecture/decisions/*.md` (если принято/изменено решение)

---

## 13. Источник истины

Код является источником истины.

Если `docs/architecture/*` расходится с кодом:
- приоритет у кода;
- документация обновляется в ближайшей итерации `Code Mode`.
