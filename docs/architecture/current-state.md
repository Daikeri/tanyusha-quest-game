# Текущее состояние

Обновлено 25.11.2026. Сцены 04–06, станция «МедиаЛаб» и первый ключ.

## Реализовано

- Статическое браузерное приложение без сборки. GitHub Actions подготовлен для публикации `index.html`, `join.html`, стилей и модулей из `main` на GitHub Pages.
- Обе ветки пролога сходятся в сцене 04. Сцены 04–06 показывают знакомство с Лерой и Егором, правила и первую станцию. Сокращённая конфигурация показывает три ключа и ведёт к сцене 09, полная показывает пять и ведёт к сцене 07. Сцены 07 и 09 обозначают границу текущего прохождения.
- Городская заставка с мягким движением камеры, маршруты NPC, аудитория, афиша, локальная имитация голосования, обе ветки, комната Никиты, переписка из PDF и путь к молодёжному центру.
- Никита, Соня, Лера и Егор используют общие пиксельные спрайты и портреты. В холле и медиастудии есть постановочные жесты, планшет и знак внимания.
- Сценарные команды выводят двери, возвращают телефоны в ожидание, публикуют следующую станцию, запускают мини-игру и выдают ключ. Ссылки на ресурсы и сцены проверяются перед запуском.
- Логический Canvas 960×540. На широких экранах поле 16:9; на узких вертикальных экранах фон кадрируется, интерфейс перестраивается. Диалог остаётся HTML-текстом.
- Общие паузируемые часы и отмена через AbortController. В параллельной группе недопустимы команды ожидания пользовательского ввода, смены локации и переходов.
- Локальный адаптер выбора: 30 секунд, ручное задание А/Б, досрочное завершение, ожидание при незаданной ветке, подтверждение продолжения пробелом. Готовый результат нельзя изменить.
- Пауза, звук и полноэкранный режим управляются кнопками в верхней строке. На экране окончания можно запустить историю заново. При скрытии вкладки выполняющееся прохождение ставится на паузу. Выбор ветки и завершение отсчёта доступны прямо на экране голосования.
- Процедурная музыка и короткие звуки Web Audio. Включение контекста — после действия пользователя. Голосование приглушает музыку, пауза заглушает звук. Ошибка запуска аудио не препятствует сюжету.
- Состояние сюжета хранится в памяти ведущего. Количество ключей и конфигурация хранятся в `GameState`; сетевой снимок прогресса реплицируется в `rooms/$room/quest`, доступный на чтение участникам комнаты. Ключ за МедиаЛаб выдаётся по завершении станции.
- «Вирусный ролик» использует общий 90-секундный дедлайн, который ведущий может приостановить вместе с игрой. Телефон проверяет монтаж и заголовок, сохраняет черновик и этап локально для той же комнаты, а раннее завершение переводит участника в ожидание. Истечение времени блокирует дальнейшие правки; ведущий подтверждает продолжение сюжета. Локальная репетиция использует тот же редактор с игровыми часами.
- Firebase Authentication использует аккаунт ведущего и анонимные учётные записи участников. В Realtime Database сохраняются комнаты, участники, открытый вопрос, ответы и результат. Правила проверяют UID, членство в комнате, статус и срок приёма ответа. Закрытие с подсчётом голосов выполняется транзакцией.
- Корневая страница открывается на форме входа ведущего. Пароль остаётся в поле до успешного входа или перехода к локальной репетиции. После входа и подтверждения записи комнаты в Firebase блок с QR, ссылкой и счётчиком участников примыкает к верхнему и правому краям игровой секции. После ошибки подготовки можно повторить подключение. Локальная репетиция доступна с экрана входа.
- Перезапуск сетевой истории закрывает прежнюю комнату и автоматически открывает новую. QR ведёт на мобильную страницу в той же папке сайта. При запуске с loopback используется публичный адрес GitHub Pages. Результат публикуется при продолжении сюжета, а при ничьей выбор подтверждает ведущий.

## Проверено

- 13 браузерных проверок движка без библиотек в `tests/index.html`.
- В Edge с локальным эмулятором Realtime Database проверены QR-ссылка, два участника, разграничение прав, пауза, изменение ответа, обновление страницы телефона, одновременное закрытие и запись голоса, дедлайн и публикация результата.
- В том же сценарии проверены сохранение пароля во время проверки и после ошибки входа, повтор подготовки, QR в правом верхнем углу на экранах 1280×720, 390×844, 320×640 и 844×390, создание новой комнаты при перезапуске и возврат к форме после выхода.
- Автоматическое прохождение обеих веток в Microsoft Edge через Python Playwright: пауза таймера, ручное раскрытие результата, ожидание незаданной ветки, все шесть сообщений переписки, общий финал, повторный запуск с экрана окончания и отсутствие ошибок JavaScript.
- В локальной репетиции проверены четыре и шесть дверей, переходы к сценам 09 и 07 и получение ключа при истечении времени без готового монтажа. В эмуляторе с двумя телефонами проверены пауза задания, независимость этапов, восстановление черновика, проверка заголовка, перетаскивание кадров, общий дедлайн и публикация первого ключа на оба телефона.
- Размеры окна: 1280×720, 1920×1080, 390×844; дополнительно проверены длинная реплика на узком экране, вход и выход из полноэкранного режима. Снимки для визуальной проверки сохраняются локально в `.artifacts/`, в Git не включаются.

## Пока отсутствует

Отдельный экран ведущего, сохранение всего прохождения, содержание сцен начиная с 07, оставшиеся станции и открытие секретной двери. Не проверена работа на физическом проекторе и в Safari/Firefox. Публичный запуск зависит от публикации сайта и правил RTDB.
